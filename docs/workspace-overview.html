The repository currently holds a small set of standalone interface experiments rather than a connected application. The pages explore recognizable product surfaces and a Schoolnet education homepage, giving the workspace concrete visual starting points.

01 Workspace snapshot

The current structure separates experiments from documentation. No shared application source, build command, or test suite is established yet, so these pages are best treated as visual prototypes that can inform a later product direction.

Reading the repository

Keep each experiment self-contained while the direction is still exploratory. Once a shared dashboard concept is clear, move reusable interface pieces into a named source area and document its run and validation commands.

03 A practical review flow

Use the same short loop when reviewing or extending an experiment. Step through the stages below with the buttons, nodes, or arrow keys.

→→
Step 1 · Inspect

Open one experiment at a time and note its layout, responsive behavior, interactions, and visual choices. Keep observations tied to the file so they can be revisited.

Step 2 · Compare

Compare the experiments against the intended dashboard use. Identify which patterns serve that product and which belong only to their original reference interfaces.

Step 3 · Consolidate

After a direction is selected, establish shared components, a clear source layout, and documented commands. Keep experiments as references only when they still provide value.

04 Next steps

Define the dashboard job

Write down who uses it, what information they need, and the main decision or task it should support.

Choose a reference direction

Use the current pages as inspiration where useful, while keeping product requirements in control of the resulting interface.

Establish the application shape

Choose a framework only when the first real feature needs it. Then add source organization, formatting, and run instructions.

Document as it takes shape

Update this workspace overview when the structure or purpose changes, and record commands once they are real and repeatable.
